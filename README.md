# Alfred TravelTech Spec

Системная спецификация сервиса мониторинга рейсов и актуализации плана поездки. Исходники написаны на Markdown, диаграммы — на Mermaid. Сайт собирается с помощью Material for MkDocs.

## Разделы

1. Бизнес-контекст и границы проекта.
2. Функциональные требования и критерии приёмки.
3. Модели процессов.
4. Архитектура и API.
5. Модель данных.
6. NFR и System Design.
7. Архитектурные решения, риски и проверка.

## Просмотр локально

Нужен Python 3.10 или новее.

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
mkdocs serve
```

Откройте адрес из терминала, обычно `http://127.0.0.1:8000`.

## Публикация на GitHub Pages

1. Распакуйте архив и загрузите **содержимое** папки проекта в корень нового репозитория. Не забудьте скрытую папку `.github`.
2. Проверьте, что основная ветка называется `main`. Для другого названия измените `branches` в `.github/workflows/deploy-docs.yml`.
3. В репозитории перейдите в **Settings → Pages → Build and deployment** и выберите **Source: GitHub Actions**.
4. Отправьте изменения в `main` либо запустите workflow вручную: **Actions → Deploy documentation to GitHub Pages → Run workflow**.
5. После успешного выполнения адрес сайта появится в **Settings → Pages**. Для обычного репозитория адрес имеет вид `https://<пользователь>.github.io/<репозиторий>/`.

Для обычного публичного репозитория сайт также будет публичным. Доступность Pages зависит от настроек и тарифа GitHub.

## Редактирование

Все страницы находятся в `docs/`. Файл `mkdocs.yml` задаёт тему и меню; `docs/stylesheets/extra.css` содержит небольшие стилистические настройки. Диаграммы Mermaid встроены прямо в Markdown и отображаются стандартными средствами Material for MkDocs. При push в `main` сайт пересобирается автоматически.

Спецификация описывает проектное решение: реальные поставщики, порог задержки, численные SLA и сроки хранения должны быть согласованы отдельно.

Для удобства чтения рядом с каждой диаграммой есть ссылка на её полноразмерное изображение в `docs/assets/diagrams/`. После изменения Mermaid-исходника в Markdown переэкспортируйте соответствующий PNG и замените его в этой папке; встроенная диаграмма на сайте обновляется из Markdown автоматически.
